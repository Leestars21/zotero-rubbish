# Zotero Rubbish 文献筛选

中文 | [English](README.en.md)

项目主页：[Leestars21/zotero-rubbish](https://github.com/Leestars21/zotero-rubbish)

根据你本次提供的研究方向和画像，对 Zotero 文献做适配评分，再通过一个
本地阅读页面完成人工判断。你明确要求执行后，AI 将确认不合适的文献移出
全部原分类并加入 **!Rubbish**，保留原文献、PDF、笔记、批注和阅读记录。

## 适合什么场景

- 对整个文库或某个主题分类做阅读前筛选，默认包含所选分类的子分类。
- 按研究方向、方法基础和当前需要安排阅读顺序。
- 阅读后批量隔离不适合当前研究的文献，记录理由，方便以后找回或恢复。

采用简单的 0–5 分适配评分，附依据和理由。默认先看元数据与摘要，必要时
补读正文；证据不足单独标为待补证据。低分只用于安排阅读，不自动触发移动。
暂时看不懂的文献可以标为“暂缓”。

## 阅读页面

无需安装新插件或运行常驻服务，打开生成的 `review.html` 即可：

1. 搜索、排序，勾选计划阅读的文献；编号保持稳定。
2. 通过链接在 Zotero 中查看条目或阅读 PDF。
3. 标记“保留”“暂缓”“移入 !Rubbish”，可批量操作、填写原因。
4. 对拟移入的文献确认已经阅读，统一导出决定。
5. 回到 AI，让它核对预览；明确要求执行后才调整 Zotero 分类。

导出一个文件即可提交全部判断，不需要反复复制论文题目。分次阅读时先
导出进度，下次重新导入。关闭页面前需要保存；页面不依赖自动保存。

**移动规则：**即使只筛选一个分类，默认也会将选中文献移出全部原分类，
使其最终只属于 !Rubbish。执行预览会列出这些分类。如希望保留某些归属，
请在执行前明确说明。PDF 和笔记继续保存在 Zotero，不复制到结果目录。

## 依赖

- Codex 或其他可以加载 `SKILL.md` 并操作本地文件的 AI 客户端。
- Zotero Desktop，以及能读文献、查询分类归属、创建分类和调整归属的
  现有集成。优先适配 llm-for-zotero MCP；仅能读取的连接无法完成移动。
- Python 3.10+，本地页面与记录工具只用标准库，无需安装额外 Python 包。
- 支持本地 HTML、文件导出与导入的现代浏览器。

真实文库移动尚未实测。首版验证覆盖虚构文库流程、本地记录和浏览器页面；
实际运行会重新核实连接、工具能力与条目状态。连接不可用时会保留进度，
说明哪一步未完成。

## 安装

### 让 Codex 安装

把下面这句话交给 Codex：

    请从 https://github.com/Leestars21/zotero-rubbish 安装 zotero-rubbish skill 到我的 Codex skills 目录，保留已有内容并验证安装。

### 手动安装

下载或克隆项目，将仓库内部的 `zotero-rubbish/` 文件夹复制到
`$HOME/.codex/skills/`（Windows 为 `%USERPROFILE%\.codex\skills\`）。
实际技能文件夹中应能直接看到 `SKILL.md`。

Windows PowerShell 示例，在尚未安装同名技能时执行：

    git clone https://github.com/Leestars21/zotero-rubbish
    Copy-Item -Recurse .\zotero-rubbish\zotero-rubbish "$env:USERPROFILE\.codex\skills\zotero-rubbish"

安装完成后新开一个 Codex 会话，检查 `$zotero-rubbish` 是否可用。
本机维护时也可以使用目录链接指向仓库内部同名技能文件夹，让修改同步到
安装入口；移动仓库前需处理链接目标。

## 使用示例

首次筛选，需要给出本次方向和画像：

    使用 $zotero-rubbish。
    我的研究方向是非均匀材料的热传导建模，当前想学习可复现的数值方法。
    我是刚开始学习这个问题的研究生，了解基础微分方程和数值计算，
    希望文献提供清楚的方法推导与复现例子。
    本次筛选「热传导」分类，包含子分类，结果保存在当前项目。
    评分后请等待我选择和阅读文献。

恢复同一批次的阅读进度：

    继续批次 <批次ID>，我确认沿用该批次的研究画像。
    我已经导出人工决定，请先核对并列出移动预览。

核对后执行：

    按该批次已阅读确认的决定执行，把标为移入的文献从全部原分类移入 !Rubbish。

之后恢复某篇：

    使用 $zotero-rubbish，继续批次 <批次ID>，确认沿用已保存的画像。
    请把 R0001 恢复到记录中的原分类，保留后来新增的其他归属。

## 本地结果与恢复

结果放在调用项目的 `.zotero-rubbish/runs/<批次ID>/`，包括研究画像与
评分、阅读页面、人工决定、操作预览和可恢复的分类记录。操作后生成
`Rubbish/操作记录.md`；未知或部分完成的状态会单独列出。

移动前保存全部原归属，操作后重新查询核实。超时先核查再续办，不重复
盲目移动。恢复时先补回原分类，再移除本流程新增的 !Rubbish 归属；保留
用户后来增加的其他归属。原分类已不存在时，需要你决定恢复目标。

本地结果带有 Git 忽略规则，不属于公开仓库内容。分享反馈时不要提交
真实研究画像、文献清单、决定文件、完整 PDF 或 Zotero 数据库。
