# Zotero 操作、核实与恢复

## 接口与范围

优先使用现有 llm-for-zotero MCP。下列是能力路由，不替代运行时工具说明：

- `library_search`：枚举文库和完整分类树；按文库、分类分页列出条目，
  请求摘要、元数据、归属和附件，必要时 `resolveToParents`。
- `library_read`：核对已知母条目的身份、归属、附件和笔记关联。
- `paper_read`：需要正文依据时定向阅读已知文献。
- `library_update`：已授权的分类创建和母条目分类归属调整。
- `undo`：如使用撤销，必须提供实际回执中的显式 action ID；独立客户端
  不能依赖“撤销上一步”的相对历史。

先核实连接和能力；枚举失败不能报告“全库已评分”。读取失败时保留已取得
的清单并标注范围缺口。写入能力不可用时完成本地预览与人工判断，告知缺失
能力，等待恢复；不要改写数据库或开发临时插件补齐。
用户未要求时不要启动程序、改变 Zotero 配置或创建定时任务。

固定本次 `libraryID`，不要随当前选中分类或工具默认范围漂移。分类名称、
key 与本地数字 ID 不等价。按完整路径解析目标与筛选范围；找不到或有多个
匹配时只询问目标选择。个人文库和组库均只在同一文库内调整归属。

## 完整枚举

全库使用明确文库的条目列表；单分类在完整分类树中展开所有纳入范围的
子分类 ID，并逐个分页。始终检查 `totalCount/returnedCount/limited`
或同等覆盖信息，推进 `offset/nextOffset` 至结束；重复页面或总数漂移
要停下来重新核对，不把第一页当全量。

跨分类对同一 `libraryID+itemKey` 去重。保留条目的全部归属，不只保留
用于找到它的分类。Zotero 中不同 key 的重复论文不自动合并或删除。
排除垃圾桶、Rubbish 及其子分类，并保存跳过数量和原因。
工具不能可靠展开子分类或解析母条目时，把该限制记录为未完成。

读取依据只描述本轮真正查看的内容。标题不足以判断时留为待补证据。
研究画像、得分或 AI 阅读不能代替人的筛选与阅读决定。

## 移动前的具体预览

从决定文件取得已由人阅读确认的条目，按已锁定的文库与 key 重新读取：

1. 母条目 key、实际数字 ID 与清单对应，条目未被删除且仍在同一文库。
2. 全部当前分类归属及各分类的 ID/key/完整路径。
3. 附件和笔记的关联 key；阅读条数受限时补足关联清单，不能把截断结果
   当作完整快照。无需复制 PDF 或笔记正文。
4. 同库顶层 `Rubbish` 的 ID，或“尚未创建”的事实。

展示文献编号、题目、原分类、拟移出范围、目标与原因。默认把**所有原分类**
移出，包括本次筛选范围之外的其他分类。用户显式保留某些分类时，采用
单独记录的例外计划，不能使用从全部来源移出的默认操作。

用户只保存决定时询问执行；具体条目和“按本批次决定执行”已有明确授权时
继续。预览后身份或归属发生实质变化时更新预览，重新解决授权是否覆盖变化，
不静默清除用户后来添加的分类。

## 写入顺序与日志

日志可持久保存是写入的前提。Rubbish 不存在时，仅在批准的移动需要它时
创建同库顶层分类。创建前保存含目标路径与授权的
`target-creation-intent.json`；创建后保存原始回执与新查询到的 ID，
不能把超时当作创建失败再创建一次。已有 Rubbish 直接复用。

目标 ID 已确定后，保存每项写入意图和原归属；工具支持时优先使用分类归属
接口的“从全部来源移动到目标”能力。现有工具说明可能提供
`kind: collections`、`mode: move`、`from: all`；**必须从当前工具说明
核实目标参数和 all 的语义**，不能仅凭字段名称猜测。

若没有可确认的合并移动操作，采用：

1. 加入 Rubbish，重新读取并确认加入成功。
2. 逐项移出快照中的来源分类，保留每步真实回执。
3. 查询最后归属；应只剩 Rubbish，附件和笔记仍关联同一母条目。

不同条目及同条目的依赖步骤顺序执行。每步落盘，区分本地
`attempt_id` 和 Zotero 实际 `action_id`；没有回执 ID 时记录缺失，不能编造。
仅调整分类归属，不修改母子关系、题名、标签、笔记、附件路径或 PDF 文件。

## 超时、部分完成与恢复

超时或断连后，先保存未核实结果，查询实际归属后再续办：

- 只剩 Rubbish 且关联未变：记录已核实，不重复移动。
- 仍为原状态：在明确原写入未发生后，按已有且仍适用的授权重试。
- 已加入 Rubbish、部分来源未移出：记录部分完成，只处理仍存在的原来源。
  后续尝试须保留最初完整快照，不能丢掉已经移出的分类。
- 出现非预览分类、母子关联改变或身份冲突：停止该条目，保留实际状态，
  询问用户解决。不可假定回执成功就全部成功。

Rubbish 创建超时也先查分类树，复用实际创建的目标。没有可靠读取接口时，
保持未核实，不以截图猜测批量操作已完成。

恢复由用户另行请求。对已核实或已核实部分完成的移动，使用完整来源快照：
先补回原分类，核实成功，再移除本流程新加的 Rubbish 归属；保留用户后来
增加的其他分类。原本无分类的文献可以恢复为未分类状态。
原分类已删除时询问用户的替代目标，不擅自重建分类结构。
如采用现有撤销接口，先按显式回执 ID 检查冲突，只使用不会覆盖后续用户
修改的撤销；有冲突时使用精确归属恢复。
